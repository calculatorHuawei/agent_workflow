### 1.2 需求描述

在现有计算器界面增加拍照入口。用户授权相机、完成拍摄后，应用识别纸面手写算式，将候选文本展示为可编辑内容；只有用户确认且文本通过字符白名单和语法校验后，才写入当前算式输入区。拒绝权限、永久拒绝、取消拍摄、识别失败、空结果及不支持字符均应可恢复，不得覆盖原输入或触发计算。

### 1.3 使用场景

用户面对纸面上的较长算式，不希望逐键输入，拍照后检查并修正识别结果，再确认填入计算器，最后由用户主动点击等号计算。

### 1.4 预期效果

- 从计算器进入拍摄流程并完成一次拍摄。
- 识别结果在填入前可见、可编辑、可重拍。
- 失败流程不崩溃、不覆盖已有表达式。
- 未经白名单和语法校验的内容不会进入求值路径。

### 1.5 背景与价值

#### 问题背景

当前 `CalculatorPage` 仅支持按钮逐字符录入；复杂纸面算式输入成本高且易错。

#### 需求价值

降低手写算式转录成本，并以“预览编辑 + 安全校验 + 用户确认”维持计算器的可控性。

#### 核心问题

输入通道缺位、相机权限异常闭环缺位、OCR 不确定结果的人工确认缺位，以及识别文本与既有计算引擎之间的安全边界缺位。

#### 不做什么（边界）

- 不在识别后自动计算。
- 不绕过用户确认直接替换当前表达式。
- 不保存或上传照片；首期固定采用端侧离线 OCR，不引入账号、网络、云端服务或远端数据处理。
- 不在本轮默认扩展计算引擎语法。
- 不支持函数、常量、变量、多行公式、方程组或 LaTeX；首期仅覆盖数字、十进制小数、基础四则运算和括号。

## 3. 需求解析报告（rq-parse）

### 3.1 意图分类

- **类型**：新增功能
- **一句话概括**：为现有计算器增加受权限控制、可确认编辑且安全校验的拍照 OCR 输入通道。
- **分类依据**：代码仓当前不存在相机、OCR、识别结果模型或入口；Issue 标题和范围均使用“支持/增加”新能力。`_orchestrator.change_type=change_requirement` 是流程路由信息，不改变需求语义分类。

### 3.2 领域映射

- **UI/交互**：拍照入口、拍摄/处理中/确认/错误/重拍状态。
- **系统能力**：相机 user_grant 权限、系统相机或 Camera Kit 调用。
- **媒体处理**：图片获取与 OCR 输入。
- **业务逻辑**：识别状态机、原输入快照、确认填入策略。
- **安全**：字符白名单、归一化、语法验证、禁止隐式执行。
- **隐私**：端侧临时处理图片，不涉及网络通信；会话结束释放图像与候选。

### 3.3 影响层次

| 层次 | 变更类型 | 说明 |
|------|---------|------|
| 表现层 | modify/new | 修改 CalculatorPage 入口；新增拍摄/确认覆盖层或页面组件 |
| 业务层 | new | OCR 编排、状态机、结果确认与填入 |
| 数据层 | new | 临时识别结果/校验结果模型；默认不持久化图片 |
| 基础设施 | new | 相机权限适配器、拍照适配器、OCR provider、表达式安全解析器 |

### 3.4 关键实体

- **数据实体**：`RecognitionSession`、`RecognitionCandidate`、`ValidationResult`、`RecognitionError`。
- **页面实体**：`CalculatorPage` 拍照入口、`Capture/RecognitionPanel`、可编辑结果输入框、错误提示。
- **接口实体**：`CameraPermissionGateway`、`CaptureGateway`、`HandwritingOcrProvider`、`RecognizedExpressionValidator`。
- **事件实体**：打开入口、权限结果、拍照完成/取消、识别成功/失败、编辑、重拍、确认、关闭。

## 4. 需求澄清（rq-clarify）

### 4.1 已确认的关键决策

| # | 问题 | 决策 | 来源 |
|---|------|------|------|
| 1 | 识别结果是否自动执行 | 否；确认后仅填入，计算仍由用户主动触发 | Issue 验收标准与安全要求 |
| 2 | 识别失败是否覆盖原输入 | 否 | Issue 验收标准 |
| 3 | 权限拒绝行为 | 给出可理解提示且不崩溃；永久拒绝提供设置引导 | Issue 功能范围 |
| 4 | 不支持字符处理 | 不得直接执行，需明确提示并允许修改/重拍 | Issue 验收标准 |
| 5 | DG-01 OCR 路线 | 首期采用端侧离线 OCR，provider 接口保留但不实现云端路径 | GitHub assignment 授权自主解决普通产品歧义；最小权限、无凭据、无隐私扩张 |
| 6 | DG-02 首期字符集 | `0-9`、`.`、`+ - × ÷ * /`、圆括号；确定性归一化 `×/x/X→*`、`÷→/`、Unicode 减号→`-`；不支持隐式乘法、函数、常量、变量和多行 | 与 Issue 示例及“基础四则”一致，避免扩展计算引擎语法 |
| 7 | DG-03 质量目标 | 100 张清晰、单行、受支持字符集的固定真值图像上表达式完全识别率 ≥90%；拍照确认到候选展示 P95 ≤2 s、超时 5 s；离线全流程可用 | 演示重点下采用可测且不过度扩张的首期基线 |
| 8 | N-01 填入语义 | 用户在预览面板显式确认后，以规范化候选替换当前表达式；确认前原表达式保持不变；不追加、不自动计算 | 单一确定语义，避免拼接形成意外表达式；确认动作提供明确数据变更点 |
| 9 | 最大候选长度 | 128 个 Unicode code unit；超限视为不可确认，可编辑或重拍 | 足够覆盖手工计算器输入，并限制异常 OCR 输出的解析成本 |

### 4.2 待定假设

- **A-01 端侧实现可用性**：目标 API 12 SDK 或可随包交付的离线组件能够提供端侧文本识别；具体 API/依赖名称在 IMPLEMENTING 的编译探针中确定。若不存在兼容实现，属于实现依赖阻塞，不自动降级到云端。
- **A-02 测试基准**：质量数据集由不少于 100 张、至少 5 名书写者、光照/角度具有轻微变化的清晰单行算式组成，且真值全部落在首期字符集内。
- **A-03 图片生命周期**：照片仅在当前前台会话内以内存或系统临时句柄存在，会话结束立即释放，不写入相册、偏好、历史或日志。

### 4.3 功能边界

- **包含**：入口、相机权限、拍照、OCR 编排、结果展示编辑、白名单与语法校验、确认填入、失败重试、原输入保护、测试设计。
- **不包含**：自动求值、历史图片、批量识别、多行公式、方程求解、函数/常量/变量、云端 OCR/存储、用户可切换 OCR 路线。

## 5. 特性清单

- **F1：拍照入口与权限闭环**：从计算器进入；区分首次申请、拒绝、永久拒绝；取消可返回。
- **F2：拍照与 OCR 编排**：获取单张图片，显示处理中状态，成功/失败均收敛到可恢复状态。
- **F3：识别结果确认与编辑**：候选文本可查看、修改、重拍、取消和确认。
- **F4：安全解析与填入**：规范化字符后执行白名单、括号/Token/语法校验；只把已验证文本填入，绝不自动调用 `onEquals()`。
- **F5：原输入保护与可测试性**：会话保存原表达式快照；除最终确认外任何路径不修改 `expression`；平台依赖通过接口隔离以支持单测替身。

## 6. 系统架构概述

```text
CalculatorPage / RecognitionPanel
          │
 RecognitionCoordinator (状态机 + 原输入快照)
   ┌──────┼──────────┐
权限网关  拍照网关   端侧 OCR Provider
                      │
       RecognizedExpressionValidator（固定首期 grammar）
                      │
        用户确认后写入 expression（不求值）
```

| 模块 | 职责 | 备注 |
|------|------|------|
| CalculatorPage | 入口与最终 expression 所有权 | 修改 |
| RecognitionPanel | 拍摄/处理中/确认/错误 UI | 新增 |
| RecognitionCoordinator | 状态转换、取消、重试、原值保护 | 新增 |
| Platform gateways | 权限和拍照系统能力隔离 | 新增 |
| HandwritingOcrProvider | OCR 抽象 | 新增；首期仅注入端侧离线实现 |
| RecognizedExpressionValidator | 归一化、白名单、语法校验 | 新增；基础四则 grammar、长度上限 128 |

不改动历史持久化语义、主题偏好、函数绘图算法和等号求值入口。

## 7. 需求规格

- **R1 相机入口与权限处理（P0，F1）**：用户可进入拍照流程；拒绝/永久拒绝/取消均不崩溃且保留原输入。
- **R2 拍摄与识别（P0，F2）**：单张清晰手写算式可提交 OCR；成功进入确认态，失败/空结果进入可重试错误态。
- **R3 结果编辑与确认（P0，F3）**：识别文本可编辑；只有用户确认后才尝试填入。
- **R4 安全解析（P0，F4）**：未通过允许字符和完整语法校验的文本不得写入求值通道；不得动态执行文本。
- **R5 原输入保护（P0，F5）**：确认前所有失败、拒绝、取消、关闭、重拍路径不改变进入会话前的表达式。
- **R6 质量目标（P0，F2/F5）**：在 A-02 固定数据集上完全识别率 ≥90%；参考支持设备上拍照确认至候选展示 P95 ≤2 s，单次 5 s 超时后进入可重试错误态；断网时完整流程可用。
