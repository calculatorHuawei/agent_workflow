# 当前算式与结果一键生成二维码 需求提案

> 来源：calculatorHuawei/agent_workflow#42（新增：将当前算式和结果一键生成二维码）
> 开发基线：`agent-test/baseline-opencalc-source`，基线 merge commit `2500bf49d79b08b135059419c422a3d49dfb4a73`（PR #41 合并后版本）

## 1. 需求概述

### 1.1 基本信息
- **功能名称**：当前算式与结果一键生成二维码（二维码分享）
- **需求类型**：新增功能
  - 备注：orchestrator 任务元数据标注 `change_type: "refactor"`，与 Issue #42 标题"**新增**：……"及正文（全新二维码分享能力 + 持久化自动化测试）不一致。按 MigBot 意图触发词表（新增/增加/开发 → 新增功能），以需求内容为准定为**新增功能**，差异在此记录备查。
- **关联全局文件**：specs/spec.md / specs/arch.md / specs/design.md

### 1.2 需求描述
用户完成一次计算并得到有效结果后，希望点击一次分享入口，看到包含"当前算式 + 当前结果"的二维码，用手机或另一台设备扫码即可读取这段计算内容，减少手工抄写。

二维码内容使用稳定、可测试的 UTF-8 文本格式：

```text
OpenCalc
算式: sin(30)
结果: 0.5
```

二维码生成必须**离线完成**（不依赖远端服务），只包含本次当前算式和当前结果，不包含整份历史记录。

### 1.3 使用场景
- 用户在 OpenCalc（HarmonyOS 计算器）中输入算式并按 `=` 得到结果（如 `sin(30)` → `0.5`）。
- 用户点击"二维码分享"入口 → 弹出二维码面板，面板同时显示人类可读的算式/结果与二维码图形。
- 另一台设备扫码 → 读到与页面显示完全一致的算式与结果文本。
- 用户关闭面板 → 返回计算器，原算式、结果、页面状态保持不变。

### 1.4 预期效果
1. 算式非空且结果有效时，一次明确操作即可打开二维码分享面板。
2. 标准二维码解码器读取面板截图得到的算式与结果，与页面当前显示完全一致。
3. 算式或结果更新后再次打开面板，二维码内容同步更新，不显示陈旧内容。
4. 无有效结果（算式为空/计算未成功/结果为错误提示）时，不生成陈旧二维码，并给出明确提示。
5. 浅色、暗色、AMOLED 三种主题下二维码均可识别（足够尺寸、对比度、静区）。
6. 面板显示人类可读的算式与结果，不扫码也能确认分享内容。
7. 关闭面板后，原算式、结果与计算器页面状态保持不变。
8. 基础计算、科学计算、函数绘图、历史记录、设置与主题能力零退化。
9. 二维码生成与载荷格式具备持久化自动化测试（普通算式、科学函数、小数、负数、长表达式、不可分享状态）。

### 1.5 背景与价值
#### 问题背景
计算完成后，把算式和结果传到另一台设备目前只能手工抄写或逐字输入，繁琐且易错；现有复制能力只覆盖结果本身（`onCopy`），不含算式，且只在本机剪贴板内。

#### 需求价值
为 OpenCalc 用户提供零网络依赖、跨设备的"算式+结果"传递通道：一次点击生成、一扫即得，降低抄写成本与转录错误率。

#### 核心问题
- 分享闭环缺位：无任何算式+结果的跨设备出口。
- 可信度要求：二维码载荷必须与页面显示逐字一致，且内容时效性必须有保障（禁止陈旧二维码）。

#### 不做什么（边界）
本次不包含（Issue #42 明确）：
- 上传二维码内容到云端；
- 分享完整历史记录；
- 二维码样式编辑、Logo 嵌入或有效期设置；
- 扫码后自动在另一台 OpenCalc 中导入并执行算式。

## 3. 需求解析报告

### 3.1 意图分类
- **类型**：新增功能
- **一句话概括**：在 OpenCalc 计算器中新增"二维码分享"能力——结果有效时一键打开面板，离线生成仅含当前算式与当前结果的 UTF-8 文本二维码，关闭面板后原状态不变，并附持久化自动化测试。

### 3.2 领域映射
- **UI/交互**：分享入口（有效性门控）、二维码面板（二维码图形 + 人类可读回显 + 关闭）、三主题适配。
- **业务逻辑**：载荷构建（固定 UTF-8 文本格式）、可分享性判定（算式非空 ∧ 结果有效 ∧ 无错误）、载荷重建时机（算式/结果更新后）。
- **系统能力**：离线二维码编码（QR 码矩阵生成）、Canvas 像素渲染（与现有绘图面板同机制）。
- **数据管理**：不涉及（不新增持久化数据，不读历史记录）。

### 3.3 影响层次
| 层次 | 变更类型 | 说明 |
|------|---------|------|
| 表现层（View） | new + extend | 新增二维码分享面板（overlay，沿用 PlotPanel/SettingsPanel 模式）；CalculatorPage 增加入口与面板开关状态 |
| 业务层（ViewModel/逻辑） | new | 新增载荷构建器与可分享性判定；新增纯 ArkTS 二维码编码器（QR 矩阵生成） |
| 数据层（Model/DAO） | 不涉及 | 不新增/修改持久化数据模型；载荷为即时构造的文本 |
| 基础设施 | extend | 本地单测入口 `List.test.ets` 注册新增测试套件 |

### 3.4 关键实体
- **数据实体**：二维码载荷文本（`OpenCalc\n算式: {expression}\n结果: {result}`，UTF-8）；二维码模块矩阵（boolean[][]，含尺寸与版本信息）
- **页面实体**：二维码分享面板（QrSharePanel，CalculatorPage 内 overlay @Builder）；分享入口（显示屏区域文字入口，横竖屏均可见）
- **接口实体**：`buildQrPayload(expression, result): string`；`encodeQr(text): QrMatrix`；可分享性判定（expression 非空 ∧ result 非空 ∧ errorMsg 为空）
- **事件实体**：打开分享面板（入口点击，门控校验）；关闭分享面板（仅复位开关状态，不触碰 expression/result）；expression/result 更新后再次打开面板时重建载荷

### 3.5 模糊点

### 3.6 复杂度评估
- **等级**：M（中等）
- **理由**：涉及 3 个技术领域（UI/交互、业务逻辑、系统能力），跨表现层与业务层；需新建独立模块（qrcode 载荷+编码器）并扩展 CalculatorPage 与测试入口；编码器本体代码量预计数百行（≥100 行阈值）；但无架构级变更（沿用现有 overlay 面板模式）、无数据模型变更、无外部接口变更。

### 4.2 待定假设
以下未明确之处采用合理默认值（实现阶段可调整，调整需在 apply-report 说明）：

## 5. 特性清单

- **F1: 二维码分享入口（有效性门控）**
  - 功能描述：在计算器主界面提供"二维码分享"入口；仅当当前算式非空、结果已有效生成且无错误提示时可进入面板；不满足条件时点击给出明确提示，不打开面板、不生成二维码。
  - 用户价值：保证入口即所得，杜绝陈旧/无效二维码（AC1/AC4）。
  - 技术要点：门控条件 `expression.length > 0 && result.length > 0 && errorMsg.length === 0`；不可分享时 toast/文字提示。
  - 子特性：
    - F1.1: 入口可见性 — 横竖屏均提供一次明确操作入口。

- **F2: 二维码分享面板**
  - 功能描述：overlay 面板同时展示二维码图形与人类可读的算式、结果文本；提供关闭操作；关闭后不改变任何计算器状态。
  - 用户价值：不扫码也能确认分享内容（AC6）；状态零扰动（AC7）。
  - 技术要点：沿用 SettingsPanel/PlotPanel 的 Stack overlay 模式与布尔开关；载荷在打开面板时由当前 expression/result 现算现用（AC3 时效性）。
  - 子特性：
    - F2.1: 内容刷新 — 每次打开面板基于最新 expression/result 重建载荷，无跨会话缓存。

- **F3: 二维码载荷构建**
  - 功能描述：按 Issue #42 固定格式构造 UTF-8 文本载荷，算式与结果逐字取页面显示值。
  - 用户价值：稳定、可测试、跨解码器一致的载荷契约（AC2/AC9）。
  - 技术要点：独立纯函数模块，无 UI 依赖；超容量时返回可识别的失败态供 UI 提示。
  - 子特性：
    - F3.1: 容量防护 — 载荷超编码上限时走"内容过长"错误提示分支。

- **F4: 离线二维码编码器（纯 ArkTS）**
  - 功能描述：UTF-8 文本 → QR 码模块矩阵，全程离线，无网络、无三方库。
  - 用户价值：离线可用的核心能力；纯函数可持久化单测。
  - 技术要点：QR byte 模式、EC 级别 M、版本自适应（1–10）、Reed-Solomon 纠错编码、掩模。
- **F5: 三主题可识别渲染**
  - 功能描述：Canvas 绘制模块矩阵；白底黑模块恒定配色 + 足够模块尺寸 + 4 模块静区。
  - 用户价值：浅色/暗色/AMOLED 三主题下均可稳定解码（AC5）。
- **F6: 持久化自动化测试**
  - 功能描述：hypium 本地单测覆盖载荷格式与编码器：普通算式、科学函数、小数结果、负数结果、长表达式、不可分享状态。
  - 用户价值：AC9 达成的直接载体；防回归。
  - 技术要点：注册进 `entry/src/test/List.test.ets`；测试可断言载荷逐字节内容与矩阵结构（定位图案/时序图案/尺寸）。

### 6.3 模块交互简述
入口点击 → 门控判定（expression/result/errorMsg）→ 通过则置 `showQrShare=true` → QrSharePanel 打开时调用 `buildQrPayload(expression, result)` 得到载荷 → `encodeQr(payload)` 得到模块矩阵 → Canvas 白底黑模块绘制（4 模块静区）→ 关闭仅复位 `showQrShare=false`。载荷与矩阵为纯函数链路，与 UI 状态单向单向流动，无缓存层。

### 6.4 明确不涉及的模块
`plot/`（FunctionPlotter/PlotAxis）、`calculator/`（Expression/CalcEngine/NumberFormatter 算法本体）、`model/`（Models/ErrorFlags 定义）、`preferences/`（PreferencesStore 与历史存储）、EntryAbility/Index 路由、构建配置（不新增依赖）。以上模块 AC8 要求零退化，本次不改动。

## 7. 需求规格

- **R1: 有效性门控的分享入口**
  - 描述：主界面提供"二维码分享"一次明确操作入口；算式非空、结果有效、无错误提示时点击打开面板；否则显示明确提示且不打开面板。
  - 需求价值：杜绝无效/陈旧二维码，保证入口即所得。
  - 使用场景：用户完成计算（或计算失败/清空）后尝试分享。
  - 验收标准：
    - AC1: `expression` 非空 ∧ `result` 非空 ∧ `errorMsg` 为空时，一次点击进入面板；
    - AC4: 算式为空、计算未成功（errorMsg 非空）或结果无效时，点击入口显示明确提示，不打开面板、不出现任何二维码。
  - 优先级：P0
  - 关联特性：F1
- **R2: 二维码分享面板与状态零扰动**
  - 描述：overlay 面板同时显示二维码图形、人类可读算式与结果；提供关闭；关闭后算式、结果、页面状态不变。
  - 需求价值：可确认分享内容（AC6）；不打断计算流（AC7）。
  - 验收标准：
    - AC6: 面板上的可读文本与页面显示的算式/结果一致；
    - AC7: 关闭面板后 expression/result/各面板开关状态与打开前一致。
  - 优先级：P0
  - 关联特性：F2
- **R3: 载荷格式与显示一致性**
  - 描述：载荷为 UTF-8 文本，格式固定为 `OpenCalc\n算式: {expression}\n结果: {result}`，仅含当前算式与当前结果；解码结果与页面显示逐字一致；内容更新后重新打开面板即得新载荷。
  - 需求价值：跨设备可信传递的核心契约（AC2/AC3）。
  - 验收标准：
    - AC2: 标准解码器读出的算式与结果与页面显示完全一致；
    - AC3: 算式或结果更新后再生成，载荷同步更新，无陈旧内容。
  - 优先级：P0
  - 关联特性：F3
- **R4: 离线生成与三主题可识别**
  - 描述：二维码编码全程离线完成，不依赖远端服务；渲染具备足够尺寸、对比度与静区，浅色/暗色/AMOLED 三主题均可识别。
  - 验收标准：
    - AC5: 三主题下截图均可被标准解码器识别。
  - 优先级：P0
  - 关联特性：F4/F5
- **R5: 持久化自动化测试**
  - 描述：二维码生成与载荷格式进入持久化自动化测试，覆盖普通算式、科学函数、小数结果、负数结果、长表达式、不可分享状态。
  - 验收标准：
    - AC9: 测试持久保存在仓库中并可重复执行（hypium 本地单测）。
  - 优先级：P0
  - 关联特性：F6
- **R6: 现有能力零退化**
  - 描述：基础计算、科学计算、函数绘图、历史记录、设置与主题能力不退化。
  - 验收标准：
    - AC8: 既有功能行为与基线一致；既有测试（含 PlotFunction.test.ets）通过。
  - 优先级：P0
  - 关联特性：F1–F6 的约束性需求
