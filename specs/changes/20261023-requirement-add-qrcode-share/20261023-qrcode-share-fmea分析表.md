# FMEA 分析表 — 当前算式与结果一键生成二维码

> 依据 dfr-fmea-general skill 对 `delta-spec.md` §7 场景用例（SC-001~SC-004，UC 共 8 个）的可靠性分析存档。
> 说明：skill 附带的故障模式库（references/hw-*-failure-mode-library.md）在当前环境中未随包提供，编号沿用系统功能通用故障模式（A 系列）惯例语义并逐条实例化；未使用 B 系列（本功能无跨进程交互消息）与 C 系列（无产品线库）。所有故障模式均结合本场景实例化，不直接套用库名。

## STEP1 理解当前需求

```markdown
【理解当前需求】

需求名称：当前算式与结果一键生成二维码（二维码分享）
需求描述：OpenCalc（HarmonyOS）用户完成有效计算后，经一次明确入口打开分享面板；
面板离线生成仅含"当前算式+当前结果"的固定 UTF-8 文本二维码，并显示人类可读回显；
关闭后计算器状态零扰动；载荷与编码具备持久化自动化测试。
功能概述：入口门控（SR-02）→ 载荷构建（SR-00）→ QR 编码（SR-01）→ 面板渲染（SR-03）→ 持久化测试（SR-04）。
功能设计描述：CalculatorPage overlay 面板（沿用基线 Stack overlay 模式）+ qrcode 纯函数模块
（QrPayload/QrEncoder，零依赖、零网络）+ hypium 本地单测。
```

### 逐用例故障模式识别 / 影响 / 原因 / 措施（按 UC 展开）

#### SC001-UC001（有效结果打开分享面板）

```markdown
【思考过程】
故障模式匹配：入口与面板链路的功能对象，匹配通用功能失效模式 A1（功能结果错误）、
A6（服务不可用→渲染不可用）、A7（异常崩溃）、A1'（陈旧结果）。
实例化并去重后保留 4 条最高可能性模式。

【故障模式表】
FM-01 QrPayload 的载荷构造功能结果错误（载荷与页面显示不一致）；A1
FM-02 QrEncoder 的矩阵生成功能结果错误（矩阵非法/不可解码）；A1
FM-03 QrEncoder 的编码功能异常崩溃（未处理异常冒泡到面板）；A7
FM-04 QrSharePanel 的载荷获取功能结果陈旧（复用上次内容未现算）；A1

【故障影响】
FM-01 自身：载荷错误；下游：编码出错误二维码；最终系统影响：用户分享错误内容，违背 AC2；严酷度 II
FM-02 自身：矩阵非法；下游：Canvas 绘出废码；最终系统影响：扫码失败/误读，AC2/AC5 失败；严酷度 II
FM-03 自身：异常抛出；下游：面板崩溃白屏；最终系统影响：应用主要功能降级；严酷度 II
FM-04 自身：载荷陈旧；最终系统影响：用户分享旧算式/旧结果，违背 AC3；严酷度 II

【故障原因】
FM-01 原因1：载荷拼接取值未使用页面显示字符串（重算/重排）；原因2：格式前缀/换行符写错
FM-02 原因1：RS 纠错码计算错误；原因2：矩阵布置（定位/时序/格式信息）错误；原因3：掩模实现错误
FM-03 原因1：超限/畸形输入未前置校验直接编码
FM-04 原因1：载荷缓存于面板级状态未随打开刷新

【改进措施】
CM-01 载荷构造收敛为 SR-00 单一纯函数，逐字取入参，持久化单测对三行结构逐字断言；关联：FM-01 原因1/2、影响
CM-04 编码器结构断言入持久化测试（尺寸公式/定位图案×3/时序图案/确定性），并以独立解码器抽样验证；关联：FM-02 原因1/2/3、影响
CM-10 编码器入口防御性校验 + 面板 try/catch 兜底显示"二维码生成失败"，禁止异常冒泡；关联：FM-03 原因1、影响
CM-02 打开面板即现算载荷，禁止载荷级缓存（面板状态不持有历史载荷）；关联：FM-04 原因1、影响
```

#### SC001-UC002（载荷与页面显示逐字一致）

```markdown
【思考过程】
本用例核心风险是字符编码正确性与格式逐字性，匹配 A1（结果错误）、A4（数据损坏）。

【故障模式表】
FM-05 QrEncoder 的 UTF-8 byte 编码功能数据损坏（×/÷/π/中文等多字节字符乱码）；A4

【故障影响】
FM-05 自身：字节序列错误；下游：解码文本乱码；最终系统影响：解码结果与页面显示不一致，违背 AC2；严酷度 II

【故障原因】
FM-05 原因1：未按 UTF-8 语义编码（按 Latin-1/UTF-16 码元截断）；原因2：字节数统计按字符数而非字节数

【改进措施】
CM-09 UTF-8 多字节编码专项单测（含 × ÷ π e 中文样例），字节级断言编码输出；关联：FM-05 原因1/2、影响
```

#### SC002-UC001（无效状态拒绝分享并提示）

```markdown
【思考过程】
核心风险是门控漏判放行，匹配 A1（结果错误：无效放行）。

【故障模式表】
FM-06 入口门控判定功能结果错误（无效状态放行生成陈旧/空二维码）；A1

【故障影响】
FM-06 最终系统影响：用户扫到空/陈旧内容，违背 AC4；严酷度 II

【故障原因】
FM-06 原因1：门控条件遗漏 errorMsg 分支；原因2：判定时机在状态更新前

【改进措施】
CM-03 门控三分支（expression 为空 ∨ result 为空 ∨ errorMsg 非空）前置判定，不通过显示明确提示且不置 showQrShare；三分支单测覆盖；关联：FM-06 原因1/2、影响
```

#### SC002-UC002（超长表达式容量防护）

```markdown
【思考过程】
容量边界风险，匹配 A6（编码不可用）、A7（异常崩溃）。

【故障模式表】
FM-07 QrEncoder 的超容量输入处理功能服务不可用（超限输入崩溃或产出残缺矩阵）；A6/A7

【故障影响】
FM-07 最终系统影响：面板崩溃或显示残缺码，误导用户；严酷度 III

【故障原因】
FM-07 原因1：无容量前置判定，版本越界数组越界；原因2：容量按字符数而非 UTF-8 字节数计算

【改进措施】
CM-06 容量前置判定（271 字节，EC-M v10）在 SR-00 载荷层执行，超限返回失败态 → 面板显示"内容过长"明确提示；边界值（上限通过/超限拒绝）入持久化单测；关联：FM-07 原因1/2、影响
```
