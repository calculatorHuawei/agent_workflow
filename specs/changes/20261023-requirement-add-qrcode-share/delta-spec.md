## 1. 需求描述

| **设计资产** | **描述** |
| ------------ | -------- |
| IR标识 | IR-R1（有效性门控的分享入口）、IR-R2（二维码分享面板与状态零扰动）、IR-R3（载荷格式与显示一致性）、IR-R4（离线生成与三主题可识别）、IR-R5（持久化自动化测试）、IR-R6（现有能力零退化） |
| 名称 | 当前算式与结果一键生成二维码（二维码分享） |
| 描述 | 用户完成一次计算并得到有效结果后，通过一次明确操作打开二维码分享面板；面板离线生成仅含"当前算式 + 当前结果"的 UTF-8 文本二维码（`OpenCalc\n算式: {expression}\n结果: {result}`），并显示人类可读回显；关闭面板后计算器状态零扰动；二维码生成与载荷格式具备持久化自动化测试。 |
| Who | OpenCalc（HarmonyOS 计算器）终端用户 |
| Where | OpenCalc 应用内计算器主页面（竖屏/横屏），二维码分享面板（overlay） |
| When | 当前算式非空且计算已得到有效结果时 |
| Why | 现有复制能力仅覆盖结果、仅限本机剪贴板，跨设备传递算式+结果只能手工抄写，繁琐易错 |
| What | 有效性门控的分享入口、二维码分享面板（二维码图形+人类可读回显+关闭）、固定格式 UTF-8 载荷、纯 ArkTS 离线二维码编码、三主题可识别渲染、持久化自动化测试 |
| How | CalculatorPage 新增入口与 overlay 面板（沿用既有 Stack overlay 模式）；新增 qrcode/QrPayload 与 qrcode/QrEncoder 纯函数模块；Canvas 绘制模块矩阵；hypium 本地单测持久化 |
| 类别 | 设计类（新增模块 + 新增 UI 面板） |

### 价值

为 OpenCalc 用户提供零网络依赖、跨设备的"算式+结果"传递通道：一次点击生成、一扫即得，消除手工抄写成本与转录错误。载荷与页面显示逐字一致（AC2）构成可信传递契约；时效性保障（AC3/AC4）杜绝误导性陈旧内容；持久化测试（AC9）防止能力回归。

## 2. 术语与缩写

| 术语/缩写 | 定义 |
| --------- | ---- |
| QR 码 | Quick Response Code，二维矩阵条码；本文指 ISO/IEC 18004 标准二维码 |
| 载荷（payload） | 编码进二维码的 UTF-8 文本，格式固定为 `OpenCalc\n算式: {expression}\n结果: {result}` |
| 模块（module） | QR 码中的最小黑白方块单元；模块矩阵为 boolean[][]（true=深色） |
| 静区（quiet zone） | 二维码图形四周的空白边框，本规格要求 ≥ 4 模块宽 |
| 定位图案（finder pattern） | QR 码三个角上的"回"字形图案，解码器据此定位 |
| 时序图案（timing pattern） | QR 码中连接定位图案的黑白交替线 |
| RS 纠错 | Reed-Solomon 纠错编码，QR 码内置的容错机制 |
| EC 级别 | Error Correction Level，纠错等级；本规格采用 M（约 15% 可纠错） |
| 掩模（mask） | 为避免大面积同色区域而对模块矩阵施加的异或图案 |
| 版本（version） | QR 码尺寸规格，版本 V 为 (4V+17)×(4V+17) 模块；版本 1=21×21，版本 10=57×57 |
| 门控（gating） | 分享入口的前置有效性判定：算式非空 ∧ 结果非空 ∧ 无错误提示 |
| overlay 面板 | Stack 容器内全屏/卡片式覆盖层，沿用基线 SettingsPanel/PlotPanel 模式 |
| AMOLED 主题 | themeIdx=1 纯黑背景主题（#000000）；另有 0=浅色（#FFFFFF）、2=暗色（#121212） |

## 5. 假设和约束

| 序号 | 约束类别 | 约束描述 | 对验收的影响 |
| ---- | -------- | -------- | ------------ |
| 1 | 功能边界 | 仅分享当前算式与当前结果，不分享历史记录（Issue #42 明文） | 载荷不得读 history 数组；AC2 验证仅比对当前显示 |
| 2 | 功能边界 | 不做云端上传、样式编辑、Logo、有效期、扫码端自动导入 | 不引入网络能力；验收不含相关项 |
| 3 | 技术约束 | 二维码生成必须离线完成，不依赖远端服务 | 编码器须为进程内纯函数；禁止任何网络调用路径 |
| 4 | 技术约束 | 项目零第三方依赖惯例（基线 oh-package dependencies 为空） | 编码器自研纯 ArkTS 实现；不新增 oh-package 依赖 |
| 5 | 质量约束 | 三主题（浅色/暗色/AMOLED）下均可识别 | 渲染采用恒定白底黑模块 + 静区，不随主题变色 |
| 6 | 质量约束 | 载荷与页面显示逐字一致（AC2） | 载荷取值唯一来源为页面当前 expression/result 字符串，禁止重算/重排 |
| 7 | 状态约束 | 关闭面板后状态零扰动（AC7） | 面板逻辑仅允许复位自身开关状态 |
| 8 | 兼容约束 | 基础计算、科学计算、函数绘图、历史记录、设置与主题零退化（AC8） | plot/、calculator/、model/、preferences/ 模块零改动；既有测试保持通过 |
| 9 | 假设（待定） | 分享入口置于显示屏（DisplayPanel）区域，横竖屏均可见 | AC1 仅要求"一次明确操作"，不限定位置；实现阶段可微调 |
| 10 | 已确认约束 | 编码参数 EC-M、版本 1–10；byte 模式有效上限为 213 字节，载荷超限走"内容过长"错误提示分支 | Developer 风险记录与编码器容量表已证实；不再使用错误的 271 字节口径 |
| 11 | 过程约束 | Developer 流程：Planning → Implementing → Applying（RED→GREEN→REFACTOR）；Tester 独立验证；Reviewer 双审 | 本 SPEC 的 AC 需可被独立 Tester 以真实 UI 操作+解码工具验证 |

### ADD 用例 SC001-UC001：有效结果打开分享面板

##### 简要说明

验证门控放行路径：有效结果下一次点击入口 → 面板弹出 → 载荷现算 → 二维码渲染成功。

##### Actor

| 角色 | 类型（主/次，人/系统） | 与系统的关系 |
| ---- | ---------------------- | ------------ |
| 终端用户 | 主，人 | 操作计算器与分享面板 |
| 外部扫码设备 | 次，系统 | 消费二维码画面（场景外验证） |

##### 前置条件

| 场景要素 | 本用例采用的取值 | 对用例的影响点（触发/步骤/分支/数据/DoD） |
| -------- | ---------------- | ----------------------------------------- |
| **T** 生命周期阶段 | 运行态 | 触发入口可见 |
| **G** 场景目标 | 打开面板并生成二维码 | 决定 DoD：面板可见且含二维码 |
| **E** 环境 | OpenCalc 前台 | 步骤可执行 |
| **A** 参与者 | 终端用户 | 执行点击 |
| **S** 系统状态 | expression="sin(30)"，result="0.5"，errorMsg="" | 门控判定通过的数据基础 |

##### 最小保证

门控判定失败或编码异常时，不打开面板或不显示二维码，并给出明确错误提示；计算器状态不被改变。

##### 成功保证（后置条件）

1. 分享面板可见，包含二维码图形与人类可读的算式/结果文本；
2. expression/result/errorMsg 保持打开前取值。

##### 触发事件

用户点击显示屏区域"二维码分享"入口。

##### 主成功路径（基本事件流）

```
1. 用户输入 sin(30) 并按 =，页面显示结果 0.5
2. 门控判定：expression 非空 ∧ result 非空 ∧ errorMsg 为空 → 通过
3. 置 showQrShare=true，挂载二维码分享面板（overlay）
4. 面板打开即调用 buildQrPayload("sin(30)", "0.5") 生成载荷
   "OpenCalc\n算式: sin(30)\n结果: 0.5"（UTF-8）
5. encodeQr(载荷) 生成模块矩阵（EC-M，版本自适应）
6. Canvas 以白底黑模块绘制矩阵（含 4 模块静区），面板同时显示人类可读回显
```

##### 扩展路径

```
4a. 载荷超出编码容量上限
    → 面板显示"内容过长，无法生成二维码"，不渲染二维码（见 SC002-UC002）
5a. encodeQr 抛出异常（防御性兜底）
    → 面板捕获并显示"二维码生成失败"，不崩溃、不显示残缺图形
```

##### 验证达成标准

```
Given 算式 sin(30) 已计算得到有效结果 0.5 且无错误提示
When  用户点击"二维码分享"入口
Then  二维码分享面板弹出
And   面板内显示二维码图形与人类可读文本"算式: sin(30)"、"结果: 0.5"
And   使用标准解码器扫描截图得到 "OpenCalc\n算式: sin(30)\n结果: 0.5"
```

### MOD 用例 SC005-UC002：更新内容后的截图载荷同步

##### 简要说明

用独立解码结果而非人类可读回显证明重开后的二维码载荷已更新。

##### Actor

| 角色 | 类型（主/次，人/系统） | 与系统的关系 |
| ---- | ---------------------- | ------------ |
| Tester | 主，人 | 执行两次计算与截图 |
| 标准二维码解码器 | 次，系统 | 比较两张截图载荷 |

##### 前置条件

| 场景要素 | 本用例采用的取值 | 对用例的影响点（触发/步骤/分支/数据/DoD） |
| -------- | ---------------- | ----------------------------------------- |
| **T** 生命周期阶段 | 修复验证 | 在同一安装与会话完成 |
| **G** 场景目标 | 证明 QR 本体内容更新 | 不能只看面板文字 |
| **E** 环境 | 任一已通过主题，建议 light | 固定环境减少变量 |
| **A** 参与者 | Tester + 独立解码器 | 输出两份解码日志 |
| **S** 系统状态 | 首次 1+2=3，随后 2+3=5 | 两个期望载荷明确 |

##### 最小保证

关闭与重开过程中计算器状态不被意外清除；如第二次绘制失败，不得保留第一次二维码。

##### 成功保证（后置条件）

第一张截图解码为 `1+2/3`，第二张截图解码为 `2+3/5`，且两者不同。

##### 触发事件

Tester 关闭首次面板，更新计算后再次打开并截图。

##### 主成功路径（基本事件流）

```text
1. 完成 1+2=3，打开、截图、独立解码
2. 关闭面板，完成 2+3=5
3. 重开面板，等待布局稳定、截图、独立解码
4. 对比两次载荷与各自页面显示
```

##### 扩展路径

```text
3a. 第二次 Canvas 尚未稳定
    等待明确的 UI 稳定条件后取证，不使用第一帧或旧截图
4a. 第二次仍解码为旧载荷
    本用例失败，记录为陈旧二维码
```

##### 验证达成标准

```text
Given 第一次设备截图已解码为 "OpenCalc\n算式: 1+2\n结果: 3"
When 用户关闭面板、完成 2+3=5 并重新打开后保存第二张设备截图
Then 第二张截图解码为 "OpenCalc\n算式: 2+3\n结果: 5"
And 第二张截图不包含第一次载荷
```
