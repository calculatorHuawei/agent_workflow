# 计算结果小数/分数切换需求 SPEC

---

## 1. 需求描述

| **设计资产** | **描述** |
| ------------ | -------- |
| IR标识 | IR-44 |
| 名称 | 计算结果小数/最简分数切换 |
| 描述 | 在同一次成功计算的结果区域中切换小数与最简分数显示，切换不重新求值且不改变表达式或历史记录 |
| Who | 学生用户及需要精确比例表达的计算器用户 |
| Where | OpenCalc HarmonyOS 主计算页面结果区域 |
| When | 已完成一次无错误计算并存在有限数值结果时 |
| Why | 小数不总是适合教学和分数运算；历史 #27 的旧算法无法满足 `1÷3 → 1/3` |
| What | 模式切换、可靠有理逼近、最简化、整数/负数规则、安全降级、自动化测试 |
| How | 保留 raw result；通过有界连分数生成候选；误差门禁失败时回退现有小数快照 |
| 类别 | 设计类 |

### 价值
让学生无需重复输入即可比较小数和分数表达；以可验证的误差门禁避免把非有理结果伪装成精确分数，同时保持现有计算、历史与错误处理行为。

## 2. 术语与缩写

| 术语/缩写 | 定义 |
| --------- | ---- |
| raw result | `CalcEngine.evaluate` 返回且尚未格式化的 `number` |
| 小数快照 | 按现有 `NumberFormatter` 策略生成、用于显示和历史写入的字符串 |
| 最简分数 | 分子与正分母最大公约数为 1 的 `a/b`；分母为 1 时仅显示整数 |
| 有界有理逼近 | 在最大分母约束内，用连分数寻找接近浮点值的有理候选 |
| 可靠转换 | 候选同时满足有限值、安全整数、分母上限与误差门禁 |
| 降级 | 分数转换不可靠时保持既有小数展示 |

## 5. 假设和约束

| 序号 | 约束类别 | 约束描述 | 对验收的影响 |
| ---- | -------- | -------- | ------------ |
| 1 | 计算精度 | 小数显示必须复用现有格式化结果，不在本需求中改变精度策略 | 小数 AC 以当前基线为准 |
| 2 | 转换可靠性 | 最大分母默认 10000；候选误差必须 ≤ `max(1e-12, abs(value) * 1e-12)` | `1/3` 可通过；π 等常见无理值不得因粗糙候选通过 |
| 3 | 数值安全 | 分子、分母及中间收敛项必须为安全整数；迭代设置上限 | 超界时降级，不抛异常 |
| 4 | 历史一致性 | 切换不得新增、删除、重排或改写 `HistoryItem[]` | 切换前后深比较一致 |
| 5 | 范围 | 模式只作用于当前结果区域；历史条目保持计算时的小数快照 | 历史面板内容不随切换变化 |
| 6 | 生命周期 | 显示模式不要求跨应用启动持久化 | 重启默认小数，不纳入 AC |
| 7 | 错误态 | 无成功结果或存在错误时不可执行有效切换 | 按钮隐藏或禁用均可，需可测 |
| 8 | 阶段 | 本文仅规格，不授权产品源码实现 | PLANNING 完成不等于功能完成 |

## 6. 分级规格

本需求不涉及资源负载或运行状态等级；不适用主要资源分级和迟滞状态机。

### 6.1 结果显示状态
| 状态 | 进入条件 | 展示 | 允许切换 |
|------|---------|------|---------|
| EMPTY | 尚无成功结果或已 AC | `0`/现有空态 | 否 |
| DECIMAL | 成功结果，默认或从分数切回 | 既有小数快照 | 是 |
| FRACTION | 成功结果且用户切换到分数 | 最简分数；不可靠时仍显示小数快照 | 是 |
| ERROR | 求值错误 | 既有错误消息 | 否 |

### 6.2 状态机规则
- 成功求值：`EMPTY/ERROR/DECIMAL/FRACTION → DECIMAL`，建立新的 raw result 和小数快照，并按既有逻辑新增一次历史。
- 切换：`DECIMAL ↔ FRACTION`，只变更显示模式。
- AC：任意状态 → `EMPTY`，清除表达式、当前结果与 raw 缓存；既有历史不变。
- 求值错误：进入 `ERROR`，不得复用旧 raw result 显示分数。

### [MOD] 用例 SC001-UC001：`1÷2` 双向切换

##### 简要说明
用户计算 `1÷2` 后在同一结果上往返切换。

##### Actor
| 角色 | 类型（主/次，人/系统） | 与系统的关系 |
| ---- | ---------------------- | ------------ |
| 学生用户 | 主，人 | 输入并切换结果形式 |
| CalculatorPage | 次，系统 | 求值编排、状态与展示 |

##### 前置条件
| 场景要素 | 本用例采用的取值 | 对用例的影响点 |
| -------- | ---------------- | -------------- |
| T | 前台运行 | UI 可交互 |
| G | 双向对照 | 必须保存同一 raw result |
| E | 任意受支持方向/主题 | 控件可见且可点击 |
| A | 用户 | 点击等号与切换入口 |
| S | 初始 DECIMAL | 首次显示 `0.5` |

##### 最小保证
任何转换异常均保留 `0.5`，表达式和历史不变，应用不崩溃。

##### 成功保证（后置条件）
1. 分数模式显示 `1/2`。
2. 切回小数仍显示进入切换前的 `0.5`。
3. 历史仅有等号操作生成的一条快照。

##### 触发事件
用户计算 `1÷2` 并点击小数/分数切换入口。

##### 主成功路径（基本事件流）
```
1. 用户输入 1÷2 并点击 =。
2. 系统求值一次，保存 raw=0.5、小数快照=0.5，并按既有规则写历史。
3. 用户点击切换入口。
4. 系统将 raw=0.5 转换并显示 1/2。
5. 用户再次点击，系统显示原小数快照 0.5。
```

##### 扩展路径
```
3a. 转换返回 null：保持 0.5，不改变模式之外的状态。
```

##### 验证达成标准
```
Given 当前表达式为 1÷2 且小数结果为 0.5
And   历史已记录该次计算
When  用户切换到分数模式
Then  当前结果显示 1/2
And   表达式、raw result 和历史内容不变
When  用户切回小数模式
Then  当前结果显示 0.5
```

##### 约束与影响（可选）

2. 不调用 `PreferencesStore.setHistory`。

### [MOD] 用例 SC003-UC001：多次切换一致性

##### 简要说明
切换只改变 `displayMode`，复制读取当前可见展示；历史仍保存原小数快照。

##### Actor
| 角色 | 类型（主/次，人/系统） | 与系统的关系 |
| ---- | ---------------------- | ------------ |
| 学生用户 | 主，人 | 连续点击切换 |
| CalculatorPage | 次，系统 | 管理页面状态 |

##### 前置条件
| 场景要素 | 本用例采用的取值 | 对用例的影响点 |
| -------- | ---------------- | -------------- |
| T | 成功计算后 | 历史已有一次写入 |
| G | 状态一致 | 除模式外状态不可变 |
| E | 历史面板可见或隐藏 | 内容必须相同 |
| A | 用户 | 连续切换 |
| S | 有有效 raw result | 切换可执行 |

##### 最小保证
即使转换失败，历史与表达式仍不变。

##### 成功保证（后置条件）
N 次切换后表达式、raw result、decimal result 与历史深度相等；只允许 `displayMode` 和派生可见文本变化。

##### 触发事件
用户连续点击小数/分数入口。

##### 主成功路径（基本事件流）
```
1. 测试记录表达式、raw、decimal 和历史快照。
2. 用户切换 N 次。
3. 系统仅翻转 displayMode 并重新派生展示。
4. 测试比较记录值与当前值。
```

##### 扩展路径
```
2a. 用户点击 AC：进入 EMPTY，当前结果清空；历史仍不变。
```

##### 验证达成标准
```
Given 已完成一次计算并保存表达式、raw result 和历史快照
When  用户在小数和分数之间切换至少两次
Then  表达式、raw result、decimal result 和历史快照均未变化
And   未再次调用求值或历史写入路径
```
