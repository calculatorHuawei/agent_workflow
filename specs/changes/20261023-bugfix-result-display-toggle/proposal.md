# 计算结果小数/分数切换需求提案

> **Tester 反馈再规划（2026-10-23）**：产品功能、主机测试、构建、lint 与模拟器 UI 行为均已通过。当前唯一未通过门禁是结果显示 UI 套件未持久化到编排器约定目录 `D:/huawei/Demo/calculatorHuawei/orchestrator/ui_cases/`。本次 PLANNING 仅补充该测试资产的需求与设计，不变更产品源码，不重做已通过的产品实现。

## 1. 需求概述

### 1.1 基本信息
- **功能名称**：计算结果小数/最简分数切换
- **需求类型**：缺陷修复（编排载荷 `change_type=bugfix`；产品语义为恢复历史 Issue #27 未进入当前主线的能力）
- **关联 Issue**：#44；历史 Issue #27
- **关联全局文件**：`specs/spec.md` / `specs/arch.md` / `specs/design.md`

### 1.2 需求描述
在同一次成功计算的结果区域提供“小数 / 分数”切换入口。分数模式将可可靠识别的有理结果显示为最简分数；小数模式继续遵循现有格式化策略。切换只改变当前结果的呈现，不重新求值、不改写表达式、不新增或改写历史记录。

### 1.3 使用场景
学生完成 `1÷2`、`1÷3`、`2÷4` 或负数运算后，按学习需要在 `0.5` 与 `1/2`、现有精度小数与 `1/3` 等表示之间切换。

### 1.4 预期效果
- `1÷2`：`0.5` ↔ `1/2`
- `1÷3`：现有精度小数 ↔ `1/3`
- `2÷4`：`0.5` ↔ `1/2`
- 整数在分数模式显示为整数，负号只出现在分子前
- 不可可靠转换的值保留现有小数显示，且不崩溃、不伪造精确分数

### 1.5 背景与价值
#### 问题背景
当前主线 `CalculatorPage` 仅保存格式化后的小数字符串。历史 Issue #27 曾在独立分支实现切换，但其十进制定标算法明确把 `1/3` 判为不可转换，与本次 AC 冲突，且该实现未存在于当前主线。

#### 需求价值
为学生用户提供更符合课堂、作业和心算场景的结果表达，同时保持现有计算、历史和错误处理行为稳定。

#### 核心问题
当前结果管线缺少“原始数值 + 展示模式”的分离，也缺少能够识别循环小数近似值的有界有理逼近策略。

#### 不做什么（边界）
不支持分数输入、混合分数、历史条目的批量重格式化、结果编辑、任意精度有理数引擎或计算引擎重写；不要求显示模式跨启动持久化。

## 5. 特性清单

- **F1: 可靠分数转换**
  - 功能描述：把有限 `number` 结果转换为满足分母上限和误差阈值的最简分数。
  - 用户价值：常见课堂分数和循环小数近似可正确识别。
  - 技术要点：有界连分数、GCD、符号规范、可靠性门禁。
- **F2: 无副作用显示切换**
  - 功能描述：在结果区域切换当前展示值，不调用求值、不修改表达式或历史。
  - 用户价值：无需重复输入即可对照两种形式。
- **F3: 安全降级与回归保护**
  - 功能描述：非有限值、超界或误差不达标时保留小数；覆盖自动化测试。
  - 用户价值：避免崩溃和误导性结果。

- **F4: Canonical UI 回归用例持久化**
  - 功能描述：把 Tester 已执行并留存于 evidence bundle 的 version-1 JSON 用例，以项目现有约定持久化为 `orchestrator/ui_cases/result_display_toggle.json`。
  - 用户价值：Tester/Reviewer 可从稳定、相关的 canonical 输入重复执行结果切换验收，而非临时生成用例。
  - 技术要点：沿用 `function_plot.json` 的 `version/suite/cases` 结构以及 `harmony_ui_driver.load_cases()` 契约；不引入坐标、设备 ID、凭据或产品权限。

## 6. 系统架构概述

### 6.1 概念架构图
```
用户点击模式切换
        │
        ▼
CalculatorPage（模式 + raw result + 小数快照）
        ├── 小数模式/降级 ──▶ NumberFormatter（既有）
        └── 分数模式 ───────▶ FractionUtil（新增纯函数）

CalcEngine ──raw number──▶ CalculatorPage ──小数快照──▶ HistoryItem（既有、切换不写入）
```

### 6.2 核心模块职责
| 模块 | 职责 | 备注 |
|------|------|------|
| `CalculatorPage` | 缓存成功结果、维护模式、派生展示、处理点击 | 修改 |
| `FractionUtil` | 有界逼近、化简、格式化 | 新增 |
| `NumberFormatter` | 小数显示及降级 | 复用 |
| `CalcEngine` / History | 求值与历史快照 | 行为不变 |

### 6.3 模块交互简述
等号成功时仅求值一次并保存 raw 与既有小数快照；展示函数依据模式选择分数或小数。切换事件只更新模式状态。若分数转换返回 `null`，展示函数使用原小数快照。

### 6.4 明确不涉及的模块
不修改 `CalcEngine`、`Expression`、`PreferencesStore`、`HistoryItem` schema、绘图模块、路由、权限或构建依赖。

## 7. 需求规格

- **R1: 最简分数转换**
  - 描述：常见可可靠识别的有理结果输出最简分数。
  - 验收标准：`0.5→1/2`、`1/3→1/3`、`2/4→1/2`、`-0.5→-1/2`、整数不带 `/1`。
  - 优先级：P0；关联 F1。
- **R2: 当前结果显示切换**
  - 描述：成功结果存在时可在小数和分数表示间切换。
  - 验收标准：切换不重新求值，不改变表达式、raw result 或历史集合。
  - 优先级：P0；关联 F2。
- **R3: 安全降级**
  - 描述：无法可靠转换时展示既有小数快照。
  - 验收标准：NaN/Infinity/超界/误差不达标返回降级路径，无异常和伪分数。
  - 优先级：P0；关联 F3。
- **R4: 自动化验证**
  - 描述：新增纯逻辑测试与页面交互状态测试。
  - 验收标准：覆盖 Issue 全部 AC 及错误/降级边界。
  - 优先级：P0；关联 F1/F2/F3。
- **R5: 持久化 UI 用例来源**
  - 描述：在编排器 canonical 用例目录提供与 Issue #44 直接相关、可由 `load_cases()` 解析的结果显示回归 JSON。
  - 验收标准：文件路径为 `orchestrator/ui_cases/result_display_toggle.json`；`version=1`；至少覆盖 `1÷2` 双向切换、`1÷3`、`2÷4`、负数和整数；每个 case 具有唯一 `id`、自然语言 `purpose`、`expression` 与机器可读 `assertions`；来源与 Tester run-59 已执行套件一致。
  - 优先级：P0；关联 F4。
