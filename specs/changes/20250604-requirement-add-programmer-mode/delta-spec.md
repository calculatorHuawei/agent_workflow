## 系统背景

### 目的

> 在 OpenCalc HarmonyOS 计算器中新增"程序员模式"作为第三种工作模式，与现有"基础模式"和"科学模式"并列。该模式面向程序员、网络工程师、学生等专业用户，支持 DEC/BIN/OCT/HEX 四进制的实时切换、并行显示和相互转换，提升计算器在数字电子、计算机网络等场景下的实用性。

### 术语与缩写

| 术语/缩写 | 定义 |
| ----- | --- |
| DEC | Decimal，十进制（基数 10），默认数字输入方式 |
| BIN | Binary，二进制（基数 2），仅含 0/1 |
| OCT | Octal，八进制（基数 8），含 0-7 |
| HEX | Hexadecimal，十六进制（基数 16），含 0-9 + A-F |
| CalculatorMode | 计算器工作模式枚举：BASIC / SCIENTIFIC / PROGRAMMER |
| NumberBase | 数字基数枚举：DEC=10 / BIN=2 / OCT=8 / HEX=16 |
| BaseConversion | 进制转换，将同一数值的不同进制表示进行相互转换 |
| Overflow | 数值超出安全整数范围（>2^53 或 <-2^53） |
| Safe Integer | IEEE 754 双精度安全整数（-2^53 ~ 2^53，约 ±9.007×10^15） |

### 关键体验路径（KEP）

- **KEP-PRG-01**：
  - 用户目标：输入十进制 255，查看 4 进制表示
  - 路径（起点→关键步骤→终点）：基础模式 → 点击"基础"按钮切到程序员模式 → 默认 DEC → 输入 `255` → 显示屏 4 行同步显示 `DEC: 255 / BIN: 11111111 / OCT: 377 / HEX: FF`
  - 体验预期：输入即转换，零延迟，无闪烁

- **KEP-PRG-02**：
  - 用户目标：输入 HEX `FFFFFF00` 查看 DEC 表示
  - 路径：进入程序员模式 → 切到 HEX → 输入 `FFFFFF00` → 4 行同步显示
  - 体验预期：HEX 字符 A-F 可正常输入，超长输入不卡顿

- **KEP-PRG-03**：
  - 用户目标：理解 255 在各进制下的写法
  - 路径：程序员模式 → 输入 `255` → 切换 DEC/BIN/OCT/HEX 观察当前进制高亮变化
  - 体验预期：切换进制仅改变键盘字符可用性，表达式不变

- **KEP-PRG-04**：
  - 用户目标：3 次点击回到基础模式
  - 路径：程序员模式 → 点击"程序员"按钮 → 科学 → 点击"科学"按钮 → 基础
  - 体验预期：每次切换有平滑动画，状态可逆

##### 前置条件

##### 最小保证

转换失败时显示 `Overflow` 或 `Invalid`，不崩溃。

##### 成功保证（后置条件）

4 行内容与表达式数值一致。

##### 触发事件

用户在 ProgrammerKeypad 中点击数字/字母按钮。

##### 主成功路径（基本事件流）

```
1. 用户单击合法字符按钮（如 BIN 模式下的 0 或 1）
2. onDigit/onLetter 回调追加字符到 this.expression
3. this.expression 触发 @State 重渲染
4. BaseConversionPanel 计算 4 进制：
   - DEC: this.expression 直接显示
   - BIN: parseInt(this.expression, currentBase).toString(2)
   - OCT: parseInt(this.expression, currentBase).toString(8)
   - HEX: parseInt(this.expression, currentBase).toString(16).toUpperCase()
5. 4 行同步更新
```

##### 扩展路径

```
1a. 用户输入超出 2^53：
    - 该进制行显示 `Overflow`
    - 其他进制行正常显示
    - 不弹错
2a. 用户输入小数点（在 DEC 模式下按 .）：
    - 触发 onEquals 计算后 DEC 行显示小数结果
    - BIN/OCT/HEX 行显示 `（小数不支持）`
    - 提示 Toast "程序员模式仅支持整数"
```
