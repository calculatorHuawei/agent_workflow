# 需求提案: 增加%按钮

> 原始来源: GitHub Issue #1  
> 创建日期: 2026-06-09  
> 变更类型: 新增功能

## 1. 需求描述

### 1.1 一句话概括
在 OpenCalc 鸿蒙端口的计算器界面增加百分号（%）按钮，使用户能够在表达式中直接输入并执行百分比运算，核心场景是 `50 + 10% = 55`（工程语义：10% of 50 = 5）。

### 1.2 详细描述
- 终端用户在数字小键盘旁的运算符区点击 `%` 按钮，可在当前输入流追加 `%` 操作符。
- 计算引擎必须按"工程百分比"语义处理 `%`，即在加减上下文下，`A ± B%` 解析为 `A ± A*(B/100)`，从而 `50 + 10% = 55`。
- 在乘除/科学函数上下文下，`%` 退化为纯数学语义 `n% → n/100`。
- 不影响四则运算、括号、科学函数、对数、幂运算、阶乘、常数等现有功能。

## 2. 意图分类
- **类型**: 新增功能
- **理由**: Issue 标题与正文均表达"增加"一个新交互/语义维度。基础架构（按钮、解析框架）已存在但语义与执行尚未在 Issue 范围下完整收敛。

## 3. 领域映射
- **UI/交互**: 鸿蒙 ArkTS 页面 (`CalculatorPage.ets`) 的按钮排布与点击事件。
- **数据/计算**: 表达式预处理 (`Expression.ets` 中的 `getCleanExpression` / `getPercentString`)。

## 4. 影响层次
| 层次 | 变更类型 | 说明 |
|------|---------|------|
| View (pages/CalculatorPage.ets) | extend | 复用现有 `%` 按钮的渲染与点击处理；按需调整按钮区排布 |
| ViewModel / 计算服务 (calculator/Expression.ets) | modify | 调整 `%` 处理顺序，确保 `addMultiply` 不会在 `%` 前误插入 `*` |
| Model | none | 不新增数据模型 |
| 数据层 / 基础设施 | none | 不涉及持久化与外部依赖 |

## 5. 关键实体
- **页面实体**: `CalculatorPage.ets` 中的运算符按钮行（首行 `AC % ( ) ÷`）。
- **接口实体**: `Expression.getCleanExpression` / `Expression.getPercentString`。
- **事件实体**: `%` 按钮 `onClick` → `onOp('%')` → 表达式字符串追加 `%`。

## 6. 模糊点
| # | 类别 | 描述 | 严重程度 |

| 1 | 行为模糊 | 工程语义 vs 数学语义如何统一？`50+10%` 应得 55；`100*5%` 是否仍按数学语义（= 5）？ | important |
| 2 | 范围模糊 | 是否需要支持"百分比作为表达式前缀"独立使用（如 `50%` 直接得出 0.5）？ | nice-to-have |

| 5 | 兼容模糊 | 既有 `getPercentString` 实现的三分支（数字前/阶乘前/括号前）应保留还是重写？ | important |

### 9.1 关键决策
| # | 原始模糊点 | 决策 | 决策依据 |
|---|-----------|------|----------|
| D1 | 工程 vs 数学语义 | 加减上下文按工程语义 `A ± A*(B/100)`；乘除上下文与独立 `%` 按数学语义 `n% → n/100` | Issue 文本 `50+10% = 55` 直接对应工程语义；现有 `getPercentString` 已实现该三分支，保留可避免回归 |
| D2 | 三分支行为（数字前/阶乘前/括号前） | 全部保留并验证 | 现有 `Expression.ets` 已实现且在 `feat/issue-1-pct` 分支有未提交修改，需保持向前兼容 |
| D3 | 独立 `%` 输入 (`50%` → 0.5) | 范围内支持（按数学语义自动降级） | 自然衍生于 D1，无需单独实现 |
| D4 | `%` 与 `!` 组合 | 范围内支持（`5!%`、`(1+2)!%`） | 现有 `getPercentString` 已实现，独立删除会带来回归 |
| D5 | `%` 在科学函数内部 | 不在范围内 | Issue 范围未提及；如未来需要可独立 Issue |

### 9.2 假设
- 工程语义与数学语义并存不会让用户困惑（与 iOS/Android 系统计算器一致）
- `getPercentString` 在 `getCleanExpression` 中必须先于 `addMultiply` 执行（当前 `feat/issue-1-pct` 分支已实施此顺序）
- `%` 按钮的 UI 渲染与点击事件保持现状，无需新增

### 9.3 功能边界
**包含**:
- `A + B%` / `A - B%` 工程语义（数字前）
- `n%` / `A * B%` / `A / B%` 数学语义
- `(expr)%` 与 `n!%` 的工程语义处理
- `%` 按钮点击将字符 `%` 追加到当前表达式

**不包含**:
- 科学函数 `sin(30%)` 等嵌套百分号
- `%` 单独按下后立即计算（仅在按下 `=` 时计算）
- 百分号按钮的 UI 重排或样式变更（保持现状）
