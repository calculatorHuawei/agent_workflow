## 系统背景

### 目的

OpenCalc 鸿蒙端口的计算器增加百分号（%）按钮与配套的工程语义百分比计算能力，使用户能在日常计算场景（如折扣、加减百分比、税额计算）中通过 `A ± B%` 表达"基于 A 的 B 百分比"语义，并保证与系统计算器一致的体验。本变更在保持现有四则运算、括号、科学函数、对数、幂运算、阶乘、常数等功能不受影响的前提下，新增百分号交互与解析。

### 术语与缩写

| 术语/缩写 | 定义 |
| ----- | --- |
| 工程语义百分比 | `A + B%` 被解释为 `A + A*(B/100)`，例如 `50+10% = 55`；用于折扣/税等业务 |
| 数学语义百分比 | `B%` 被解释为 `B/100`；与 `*`/`/` 等上下文同用 |
| 表达式预处理 | `Expression.getCleanExpression()` 在送入 `Calculator` 解析前对原始输入字符串做的符号替换与结构调整 |
| FMEA | 失效模式与影响分析 (Failure Mode and Effects Analysis) |
| KEP | 关键体验路径 (Key Experience Path) |

- **KEP-01：% 按钮工程语义计算**
  - 用户目标：用最少的按键完成"基础值 ± 百分比"计算
  - 路径（起点→关键步骤→终点）：
    1. 启动应用进入 CalculatorPage
    2. 依次点击 `5` `0` `+` `1` `0` `%`
    3. 点击 `=`
    4. 结果区显示 `55`
  - 体验预期（可验证表述）：在 ≤ 1 秒内结果显示为 `55`，无错误提示，无 NaN/Infinity

#### 用例 UC-001-01：数字前缀工程百分号

##### 简要说明

处理表达式中以 `+`/`-` 上下文出现、且百分号前为数字字面量的情况，转换为 `A ± A*(B/100)` 形式。

##### Actor

| 角色 | 类型 | 与系统的关系 |
| --- | ------------ | ------ |
| 终端用户 | 主，人 | 通过 UI 输入并查看结果 |

##### 前置条件

| 场景要素 | 本用例采用的取值 | 对用例的影响点 | 处理方式 |
| ------------ | ------------------ | ------------------------ | --------------------- |
| **T** 生命周期阶段 | 已输入 `数字+数字` | 第二个数字追加 `%` | 扩展 |
| **G** 场景目标 | 工程语义 | 转换规则 `A+A*(B/100)` | 保持 |
| **E** 环境 | CalculatorPage | UI 路径无变化 | 保持 |
| **A** 参与者 | 终端用户 | 触发方式为点击 `%` | 保持 |
| **S** 系统状态 | 表达式非空且不含未闭合括号 | 解析前需做边界检查 | 扩展 |

##### 最小保证
- 不修改与百分号无关的输入
- 不破坏现有 `+ -` 行为

##### 成功保证（后置条件）
- 表达式被改写为 `A ± A*(B/100)` 后送入 Calculator 求值得出正确数值

##### 触发事件
- 用户点击 `%` 按钮且 `onEquals` 触发

##### 主成功路径（基本事件流）
```
1. 用户依次点击数字/运算符/数字
2. 用户点击 % 按钮
3. 用户点击 = 按钮
4. Expression.getCleanExpression() 识别 + 或 - 上下文
5. getPercentString() 将 "A+B%" 改写为 "A+A*(B/100)"
6. addMultiply() 在已无 % 的表达式上运行
7. Calculator 求值返回 55
```

##### 扩展路径
```
1a. 用户输入 "100-20%"：解析为 100-100*(20/100) = 80
2a. base 为空（连续运算符）：设置 ErrorFlags.syntax_error，UI 显示 Error
3a. 小数 "12.5+3.5%"：解析为 12.5+12.5*(3.5/100) ≈ 12.9375
```
