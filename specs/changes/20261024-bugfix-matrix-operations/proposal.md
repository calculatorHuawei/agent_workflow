# 2×2 / 3×3 矩阵运算（Issue #51）需求提案

> 规划修订：2026-10-25，PR #54 / Developer Task 61。保留 Issue #51 全量需求，并将 Tester 在精确 head `6e76305e8d3df57378314d78f30f4b53b0dc4690` 上发现的设备 TextInput 失败纳入同一变更的修复规划。本轮只更新 PLANNING 制品，不修改产品源码、`tasks.md`、提交、PR 或归档状态。

## 1. 需求概述

### 1.1 基本信息
- **功能名称**：2×2 / 3×3 矩阵运算
- **需求类型**：编排分类为缺陷修复（`_orchestrator.change_type=bugfix`）；产品语义为新增功能
- **关联全局文件**：specs/spec.md / specs/arch.md / specs/design.md
- **需求来源**：GitHub Issue #51，2026-10-24 原文（无评论补充）

### 1.2 需求描述
在 OpenCalc 中新增“矩阵”模式。用户可录入同维度的 2×2 或 3×3 方阵 A、B，执行 A+B、A-B、A×B 和 det(A)。矩阵结果保持所选维度，行列式显示标量；输入校验、维度切换、清空、数值精度和既有模式回归行为均须稳定且可观察。

### 1.3 使用场景
学生验证线性代数练习，或工程用户在移动端快速完成小规模矩阵计算，无需切换工具。

### 1.4 预期效果
矩阵模式可独立完成输入、校验、计算和结果展示；错误定位明确；切换和清空不留下陈旧结果；普通、科学、绘图以及仓库未来/既有的分数、程序员模式契约不受破坏。

### 1.5 背景与价值
#### 问题背景
PR #54 当前 head 已包含矩阵数据模型、运算引擎和输入面板；本轮规划面向 Tester 反馈的设备输入缺陷。算法独立测试 68/68、构建和 CodeLinter 已通过，但 `uitest uiInput inputText` 对首个矩阵单元格返回成功后，UI 树与截图仍为空，随后 A+B 将八个单元格全部判空。该现状证明算法正确不能替代端到端可输入性验收。

#### 需求价值
为学生和工程用户提供离线、无额外权限的小规模线性代数能力，减少工具切换。

#### 核心问题
补齐 2×2/3×3 方阵的可录入、可校验、可计算、可读结果和稳定状态转换闭环。

#### 不做什么（边界）
不做逆矩阵、转置、特征值、非方阵、混合维度或 3×3 以上矩阵；不新增网络、权限、持久化和第三方依赖。仓库旧分析文档提到“转置”，与本 Issue 非目标冲突，本次明确不采纳。

### 4.2 待定假设
- A1：矩阵输入和结果仅为会话内状态，不写入历史或 Preferences；理由是 Issue 未要求持久化，减少隐私/兼容影响。
- A2：矩阵结果用只读网格展示，det(A) 用单一标量文本展示；这是运算形状最直接的视觉表达。
- A3：维度默认 2×2；进入矩阵模式不清空上次矩阵会话状态，只有显式清空或维度切换规则改变状态；退出/返回可逆。
- A4：数值运算使用 ArkTS `number`；格式化在展示边界执行，不在每个中间乘加步骤舍入。
- A5：不为当前仓库尚未存在的分数/程序员模式补建功能，仅确保新增代码不修改其预留/未来接口，并对现存基础、科学、绘图做可执行回归。
- A6：不调用可选 `dfr-fmea-general`；本需求无外部系统、持久化或安全关键行为，可靠性风险在 spec §9 以可验证输入/状态缓解措施覆盖。
- A7：Tester 使用的 `uitest uiInput inputText` 是本项目既有设备验收路径，矩阵单元格应与普通 ArkUI 文本输入保持兼容；若驱动没有聚焦目标节点，应先修正定位/可测试标识，不把驱动问题伪装成产品值注入接口。
- A8：设备输入缺陷的修复不得改变矩阵数字语法、算法、精度、清空/切换和既有模式隔离契约。

### 4.3 功能边界
- **包含**：2×2/3×3 同维方阵 A/B；加、减、乘、A 行列式；合法十进制输入；精度格式化；错误定位；切换/清空/返回；回归和 Tester 证据要求。
- **不包含**：逆、转置、特征值、混合维度、非方阵、4×4+、矩阵持久化/历史、导入导出、复杂数。

## 5. 特性清单

- **F1：矩阵模式与维度状态**
  - 功能描述：提供入口、2×2/3×3 切换、返回和清空。
  - 用户价值：稳定进入/离开矩阵工作区，避免陈旧状态误导。
  - 技术要点：V1 `@State`；重叠单元保留；结果/错误失效。
- **F2：矩阵输入与校验**
  - 功能描述：A/B 独立单元格输入，按当前操作确定必填范围并定位错误。
  - 用户价值：错误可修复，不产生貌似有效的结果。
  - 技术要点：保留原始字符串；集中解析；全部错误一次性返回。
- **F3：矩阵运算**
  - 功能描述：加、减、乘、2×2/3×3 det(A)。
  - 用户价值：覆盖常用小规模线性代数。
  - 技术要点：无状态纯逻辑；结果形状明确；O(n³)，n≤3。
- **F4：数值展示与兼容性**
  - 功能描述：12 位有效数字消噪、整数简洁显示、既有模式隔离。
  - 用户价值：结果可读且不损害原计算器。
  - 技术要点：展示层规范化；无依赖/权限/存储变更。
- **F5：可追溯测试**
  - 功能描述：算法、边界、关键 UI、跨模式回归均关联 AC 和证据。
  - 用户价值：可独立确认功能语义与兼容性。
- **F6：设备输入闭环修复**
  - 功能描述：标准触摸/IME 与 uitest 输入均能聚焦独立矩阵单元格；文本在输入、失焦、滚动/重绘和计算后保持并参与运算。
  - 用户价值：解除 Tester 阻塞，并确保真实设备上的核心录入路径可用。
  - 技术要点：稳定 cell identity；明确单一文本状态所有权；顶层 `@State` 新引用刷新；以焦点/UI 树/截图/计算结果共同判定。

## 6. 系统架构概述

### 6.1 概念架构图
```
用户 → CalculatorPage / MatrixPanel (@State 字符串网格)
                    ↓ 校验/解析
              MatrixEngine（纯逻辑）
                    ↓ number / number[][]
              MatrixResultFormatter
                    ↓
              只读结果网格/标量/错误提示
```

### 6.2 核心模块职责
| 模块 | 职责 | 备注 |
|------|------|------|
| CalculatorPage / MatrixPanel | 模式入口、状态、网格、事件、可见反馈 | 修改/新增 Builder |
| MatrixEngine | 加减乘、det，校验结构维度和有限数 | 新增纯逻辑模块 |
| Matrix input/format helpers | 文本解析、单元格错误、精度显示 | 可与 MatrixEngine 同文件，避免过度拆分 |
| Hypium suite | 算法与边界自动化 | 新增并注册 |

### 6.3 模块交互简述
UI 收集字符串矩阵；点击操作时按操作解析 A 或 A+B；无效时返回错误映射并保持空结果，有效时调用 MatrixEngine；数值结果仅在展示边界格式化。

### 6.4 明确不涉及的模块
不修改标量 `CalcEngine`/`Expression` 语义、Preferences 数据 schema、网络、权限、路由和 HAP 划分。
