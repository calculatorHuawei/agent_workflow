## STEP 1【理解当前需求】

**需求名称**：程序员模式与 BIN/OCT/DEC/HEX 转换。  
**需求描述**：在同一 CalculatorPage 内增加 U64 四进制受限输入和同步转换，并与普通计算器稳定切换。  
**功能概述**：模式切换、合法键矩阵、精确转换、进制切换保持数值、空/非法/越界反馈、普通状态兼容。  
**功能设计描述**：CalculatorPage 负责模式与呈现；ProgrammerConverter 负责纯同步校验/解析/格式化；状态操作以完整新对象提交。

## STEP 2-1【待分析的系统元素及关联信息】

### 系统元素：ProgrammerConverter
- 功能：字符校验、U64 精确解析、范围比较、四进制格式化、状态操作。
- 下游交互：`ProgrammerOperationResult` → CalculatorPage。
- 上游交互：CalculatorPage → digit/radix/current-state 参数。

### 系统元素：CalculatorPage / ProgrammerPanel
- 功能：模式切换、键启停、结果/反馈呈现、两模式状态隔离、动画。
- 下游交互：输入事件 → ProgrammerConverter；`@State` → ArkUI 渲染。
- 上游交互：用户 → 点击事件；ArkUI → area/state 生命周期。

### 系统元素：普通计算与历史链路
- 功能：表达式、结果、历史、设置和绘图。
- 下游交互：历史写入 → PreferencesStore。
- 上游交互：CalculatorPage 普通分支 → 既有事件。

## 【各用例故障模式、影响、原因与措施】

### SC001-UC001 双向切换并保留状态
- **故障模式**：CalculatorPage 的模式切换功能产生非预期状态（A4）。
- **影响**：自身—显示错误分支；上下游—普通状态被清空或历史被覆盖；最终系统—用户上下文丢失，严酷度 III。
- **原因**：切换 handler 复用 `onAC`；普通/程序员共用 `expression/result`；切换时重建路由页面。
- **改进措施**：单一 `CalculatorMode` + 两组独立状态；同页条件分支；切换 handler 禁止写 history/preferences；往返快照测试。
- **转化 SR**：SR-03、SR-04、SR-05。

### SC001-UC002 快速切换稳定性
- **故障模式**：模式切换间歇性/非预期（A1/A4）。
- **影响**：自身—两个面板叠加或最终模式错误；上下游—点击穿透/状态不一致；最终系统—明显闪烁、误操作或崩溃，严酷度 III。
- **原因**：动画完成回调异步提交 mode；计时器错序；重复选择不幂等。
- **改进措施**：mode 同步写入、最后选择获胜；动画只呈现；选择当前模式幂等；快速序列测试。
- **转化 SR**：SR-03、SR-05。

### SC002-UC001 典型值同步转换
- **故障模式**：Converter 的转换功能结果非预期（A4）。
- **影响**：自身—四行结果不一致；上下游—页面传播错误表示；最终系统—用户基于错算结果工作，严酷度 II。
- **原因**：错误 radix、大小写/前缀格式漂移、多个结果分步更新。
- **改进措施**：单一精确值一次生成四行；完整 `ConversionResult` 返回；10/FF 固定示例测试。
- **转化 SR**：SR-01、SR-05。

### SC002-UC002 受限输入与进制切换
- **故障模式**：输入消息错误或非法（B5）；换进制功能非预期（A4）。
- **影响**：自身—非法字符进入草稿或文本被按新 radix 重解释；上下游—错误结果显示；最终系统—错算或输入不可恢复，严酷度 II。
- **原因**：只依赖 UI 禁用；UI/业务规则各自维护；换进制只改 radix 未转换草稿。
- **改进措施**：共用 `isDigitAllowed`；完整候选文本防御校验；换进制先以旧 radix 解析再格式化；失败不提交。
- **转化 SR**：SR-02、SR-05。

### SC003-UC001 空输入与恢复
- **故障模式**：空值处理部分功能/非预期（A2/A4）。
- **影响**：自身—显示旧结果或把空值当 0；上下游—用户无法判断状态；最终系统—轻度误导，严酷度 IV。
- **原因**：未区分 `''` 与 `'0'`；清空只清 input 未清 result/error。
- **改进措施**：显式 EMPTY；`result=null`；整体状态替换；AC 幂等与空后恢复测试。
- **转化 SR**：SR-02、SR-05。

### SC003-UC002 U64 边界与越界
- **故障模式**：转换功能超范围（A3）或非预期结果（A4）。
- **影响**：自身—舍入/截断/回绕；上下游—页面显示貌似合法错误值；最终系统—核心转换错误，严酷度 II。
- **原因**：使用浮点 `number`；漏比较 U64_MAX；超长文本无早停。
- **改进措施**：`bigint`/精确字符串算法；逐步上界门禁；越界无部分结果；MAX/MAX+1/跨进制往返测试。
- **转化 SR**：SR-01、SR-05。

## STEP 3【非功能性需求转化】
- **NFSR-01 / SR-05**：系统必须用精确算法处理 `[0,2^64-1]`，MAX 成功、MAX+1 返回 OUT_OF_RANGE。
- **NFSR-02 / SR-05**：非法或越界操作不得修改最后有效 input/result/radix，且必须可通过 AC/退格恢复。
- **NFSR-03 / SR-05**：模式状态同步、幂等；180ms 内重复选择后最终状态必须等于最后选择。
- **NFSR-04 / SR-05**：合法 UI 输入最多 64 个二进制字符；所有转换 O(n)、无 IO/网络/后台任务。
- **NFSR-05 / SR-04**：模式往返不得修改普通表达式、结果、历史、主题、角度、科学和绘图状态。
