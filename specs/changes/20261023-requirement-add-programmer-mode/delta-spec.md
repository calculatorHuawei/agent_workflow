# 程序员模式与四进制转换需求 SPEC

---

## 1. 需求描述

| **设计资产** | **描述** |
| ------------ | -------- |
| IR标识 | IR-45 |
| 名称 | 程序员模式与 BIN/OCT/DEC/HEX 转换 |
| 描述 | 在 OpenCalc 中增加独立程序员模式，支持受限输入、四进制同步转换、异常反馈和稳定模式切换 |
| Who | 程序员、计算机相关专业学生及需要整数进制核对的用户 |
| Where | OpenCalc entry HAP 的主计算器页面，手机与平板横竖屏 |
| When | 用户需要录入一个非负整数并查看不同进制表示时 |
| Why | 降低手工换算和跨工具切换成本，同时不破坏普通计算工作流 |
| What | 普通/程序员模式切换；BIN/OCT/DEC/HEX；合法字符约束；同步结果；空/非法/越界反馈 |
| How | 在 entry HAP 内新增独立精确整数转换组件，由 CalculatorPage 管理隔离状态并渲染轻量动画 |
| 类别 | 设计类 |

### 价值
提供可验证、精确到无符号 64 位上界的本地进制转换能力；全过程不需要网络、账号、权限或付费服务，并保持既有普通/科学计算、历史和绘图行为向后兼容。

## 5. 假设和约束

| 序号 | 约束类别 | 约束描述 | 对验收的影响 |
| ---- | -------- | -------- | ------------ |
| 1 | 数值范围 | 仅 U64；不支持负数、补码、符号位或字长切换 | 最大值成功，最大值+1失败；负号为非法字符 |
| 2 | 表示格式 | 大写、无前缀、无分组、无多余前导零；值 0 显示 `0` | 输出可直接字符串比对 |
| 3 | 精度 | 禁止使用浮点 `number` 承担 U64 精确转换；默认采用十进制字符串乘加/长除，等价替换不得改变接口或边界行为 | U64 最大值必须精确往返 |
| 4 | 状态 | 两模式草稿仅页面生命周期内保留，不跨应用重启持久化 | 重启后的程序员状态不在本次验收范围 |
| 5 | 兼容 | 不改普通表达式语法、历史存储 schema、偏好 key、绘图算法 | 回归测试应证明既有链路未被重置或重解释 |
| 6 | 权限 | 不新增权限、网络、后台任务或第三方依赖 | `module.json5` 权限清单保持不变 |
| 7 | 交互 | 默认 DEC 空输入；有效值切换输入进制时保持数值并更新草稿 | DEC 10 → BIN 后草稿为 1010 |
| 8 | 动画 | 180ms ease-in-out 的淡入/轻微位移；业务状态不依赖动画回调 | 快速点击仍得到确定最终模式，无空白帧 |
| 9 | 范围边界 | 位运算、算术表达式、前缀、浮点、转换历史、剪贴板增强不在本期 | 不得通过实现顺便扩展范围 |

## 6. 分级规格

### 6.1 能力分级

| Tier | 能力 | 依赖 | 验收重点 |
|------|------|------|----------|
| T0 | U64 校验、解析与四进制格式化 | 无 | 纯业务单测，典型值与边界精确 |
| T1 | 程序员状态转换（输入/退格/清空/换进制） | T0 | 失败不污染状态，换进制保持数值 |
| T2 | 模式/UI/动画集成 | T1 | 键启停、结果与反馈、状态隔离、横竖屏 |
| T3 | 普通功能兼容和整体回归 | T2 | 历史/表达式/结果/绘图/主题无回归 |

### 6.2 状态机规则

- `NORMAL` 与 `PROGRAMMER` 可双向切换；模式状态只有一个最终值。
- 程序员输入状态为 `EMPTY`、`VALID`、`INVALID`、`OUT_OF_RANGE`、`INTERNAL`；正常键盘路径只产生 `EMPTY/VALID`，其余状态用于防御性入口、边界和异常兜底。
- 非法或越界操作不得提交新草稿或部分结果，保留最后有效状态并更新反馈。
- 有效值换进制：先解析当前值，再以目标进制格式化并一次性提交 `radix/input/results/error`。
- 输入规范化：允许编辑过程中出现前导零，但每次成功转换后统一输出；换进制时草稿也规范化。

#### [ADD] 用例 SC001-UC001：双向切换并保留状态

##### 简要说明
普通模式已有表达式、结果和历史时进入程序员模式，输入值后再往返，两侧数据均保持。

##### Actor
| 角色 | 类型 | 与系统的关系 |
| ---- | ---- | ------------ |
| 终端用户 | 主/人 | 发起模式切换并读取状态 |
| CalculatorPage | 次/系统 | 保存状态并切换可见分支 |

##### 前置条件
| 场景要素 | 本用例采用的取值 | 对用例的影响点 |
| -------- | ---------------- | -------------- |
| T | 页面交互期 | 已完成偏好与历史加载 |
| G | 保留两模式上下文 | 不允许切换回调清空业务字段 |
| E | 任一受支持方向 | 布局变化不能重建业务状态 |
| A | 单用户 | 无并发外部写入 |
| S | NORMAL，已有表达式/结果/历史 | 作为回归快照 |

##### 最小保证
切换失败时仍停留在原模式，普通历史和计算状态不被修改。

##### 成功保证（后置条件）
1. 最终模式与最后一次用户选择一致。
2. 普通表达式、结果、历史和程序员输入/结果分别与离开前一致。

##### 触发事件
用户点击“普通/程序员”模式入口。

##### 主成功路径（基本事件流）
```text
1. 页面记录目标模式并触发 180ms 内容过渡。
2. 页面渲染程序员分支，默认 DEC 空输入或既有程序员草稿。
3. 用户输入 DEC 10，然后返回普通模式。
4. 页面恢复原普通表达式、结果和历史。
5. 再次进入程序员模式，恢复 DEC 10 及四进制结果。
```

##### 扩展路径
```text
1a. 设备旋转：响应式布局重排，但模式与两侧状态不变。
1b. 程序员输入为空：恢复空态和引导文案，不自动填 0。
```

##### 验证达成标准
```gherkin
Given 普通模式存在表达式 "1+1"、结果 "2" 和至少一条历史
When 用户进入程序员模式输入 DEC "10"，再返回普通模式并再次进入程序员模式
Then 普通表达式、结果和历史内容保持不变
And 程序员输入仍为 "10"，BIN/OCT/HEX 分别为 "1010"/"12"/"A"
```
