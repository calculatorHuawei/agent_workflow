# Proposal — 百分号按钮 (Issue #8)

## 1. 用户意图(step1)

**原始 Issue**(GitHub Issue #8):
> 加一个百分号按钮,输入 50+10% 自动算出 55

**用户角色**:计算器普通用户
**触发频次**:日常高频
**核心价值**:在加减运算中表达"上浮/下浮百分比"语义(`a+b%` ≡ `a*(1+b/100)`)
**用户故事**:作为一个想算"原价 50 上浮 10%"的用户,我希望按下 `5` `0` `+` `1` `0` `%` `=` 直接看到 `55`,而不是看到 `50.1`(`50+0.1` 的字面解释)

## 2. 需求理解(step2)

### 2.1 功能需求
- **F1**:计算器面板必须含有可点击的 `%` 按钮
- **F2**:按 `%` 时,以字符 `%` 形式追加到表达式输入框
- **F3**:按 `=` 求值时,百分号需根据上下文做"语义解读":
  - `a + b%` ⇒ `a + a × b/100`(加价语义)
  - `a − b%` ⇒ `a − a × b/100`(降价语义)
  - `a × b%` 或 `a ÷ b%` ⇒ `a × (b/100)` 或 `a ÷ (b/100)`(纯比例)
  - 单独 `b%`(无前缀运算符) ⇒ `b/100`(纯小数)
- **F4**:同时输入 `50+10%=` 必须返回 `55`(本 Issue 验收点)

### 2.2 非功能需求
- 与现有按钮风格一致(`BtnOpPct` Builder 已统一样式)
- 不引入新的依赖
- 不破坏现有 19 个按钮的布局(5 列 × 6 行)

### 2.3 业务约束
- 与 Android 原版 OpenCalc 行为对齐(本仓库源自 `Calculator.kt` 移植)

## 3. 需求澄清(step3)

cron 自动化模式下,采用以下既定决策(不询问用户):

| 议题 | 选择 | 依据 |
|------|------|------|
| `%` 处于科学模式还是基础模式 | 基础模式(顶行) | Issue 说"日常高频",且现状代码已放第一行 |
| `50%+10%` 怎么算 | `(50/100)+(50/100)*(10/100)` = 0.55 | 沿用现状 `getPercentString` 已有逻辑 |
| `−10%` 单独求值 | 视为 `-(10/100)` = -0.1 | 沿用一元负号语义 |
| 是否支持 `a^b%` | 不强求,沿用现状(`%` 不参与幂次特殊处理) | 极低频 |
| 错误场景(如 `%`+`%`) | 由 `ErrorFlags.syntax_error` 触发,UI 显示"表达式错误" | 沿用 |

## 5. 验收准则(Acceptance Criteria)

- **AC1**: 输入 `50` `+` `1` `0` `%` `=` ⇒ 显示 `55`
- **AC2**: 输入 `200` `-` `1` `5` `%` `=` ⇒ 显示 `170`
- **AC3**: 输入 `30` `%` `=` ⇒ 显示 `0.3`
- **AC4**: 输入 `2` `0` `0` `*` `1` `0` `%` `=` ⇒ 显示 `20`
- **AC5**: 输入 `(` `5` `0` `+` `1` `0` `)` `%` `=` ⇒ 显示 `0.6`
- **AC6**: 单独触发按钮 `%`,表达式输入框应追加字符 `%`(可视化反馈)
