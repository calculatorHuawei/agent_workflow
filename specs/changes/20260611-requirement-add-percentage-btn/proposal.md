# Proposal: 百分号按钮

**变更名**: requirement-add-percentage-btn
**日期**: 2026-06-11
**Issue**: #7 — 加一个百分号按钮，输入50+10%自动算出55
**类别**: UX 增强
**优先级**: ⭐ 简单需求
**类型**: 新增功能

---

## 1. 原始需求

> 加一个百分号按钮，输入50+10%自动算出55 | UX增强 | ⭐ | 日常高频，立刻感觉实用 |

## 2. 意图分类

- **类型**: 新增功能
- **一句话概括**: 在计算器按键面板增加独立的百分号 `%` 按钮，并保证按下后表达式按"加/减后基数相乘"语义自动计算（50+10% = 55，200-10% = 180）。

## 3. 领域映射

| 领域 | 说明 |
|------|------|
| UI/交互 | 在按键网格第二行第一组布局中加入 `%` 按钮（或将已有 `%` 按钮暴露更清晰） |
| 计算逻辑 | `Expression.getPercentString` 实现"基数十进制"语义 |

## 4. 影响层次

| 层次 | 变更类型 | 说明 |
|------|---------|------|
| View | modify | CalculatorPage.ets 第二行布局：把 `%` 提升到显眼的等价运算符位置 |
| ViewModel | - | 既有 `onOp('%')` 链路已通 |
| Model | - | 无 |
| 数据层 | - | 无 |
| 基础设施 | new | 单元测试框架（hypium）+ ExpressionPercentTest |

## 5. 关键实体

- **数据实体**: 无新增
- **页面实体**: `CalculatorPage` (pages/CalculatorPage.ets)
- **接口实体**: `Expression.getPercentString`, `CalcEngine.evaluate`
- **事件实体**: `onOp('%')` 事件链

## 6. 模糊点

| # | 类别 | 描述 | 严重程度 | 处置 |
|---|------|------|---------|------|
| 1 | 范围模糊 | "加一个百分号按钮"是否包含科学计算器 / 移动 / 桌面多端？ | nice-to-have | 默认仅移动端 HarmonyOS（与现状一致） |
| 2 | 行为模糊 | "50+10%=55"采用"基数十进制"还是"后置除以100"？ | important | 业界标准 = "基数相乘"语义；本项目 `getPercentString` 已经采用此语义，沿用 |
| 3 | 交互模糊 | 按钮放在哪一格？ | nice-to-have | 与已有 `AC ( ) ÷` 同行的第二槽位，颜色与运算符一致 |
| 4 | 测试 | 现状无 ETS 单元测试 | important | 新建 `entry/src/test/ets/...`，使用 `@ohos/hypium` |

## 7. 复杂度评估

- **等级**: **S（简单）**
- **理由**:
  - UI 改动 = 1 个按钮位置微调
  - 计算逻辑 = 已有 `getPercentString`，需补 RED-GREEN-REFACTOR 测试覆盖关键用例
  - 无数据模型变更
  - 无架构变更
  - 影响模块: pages/CalculatorPage.ets, calculator/Expression.ets + 1 新测试目录

## 8. 验收标准

### 功能性
- [ ] 基础模式按键面板可见 `%` 按钮，标签 `%`，位置在第二行第二槽
- [ ] 输入 `50+10%` 按等号显示 `55`
- [ ] 输入 `200-10%` 按等号显示 `180`
- [ ] 输入 `100*10%` 按等号显示 `10`
- [ ] 输入 `100/10%` 按等号显示 `1000`
- [ ] 输入 `50%` 按等号显示 `0.5`

### 非功能性
- [ ] 新增 ETS 单元测试覆盖上述全部用例
- [ ] 主题切换不破坏按钮显示（默认/暗色/AMOLED）
- [ ] 横屏布局兼容
- [ ] 历史记录正确保存含 `%` 的表达式

## 9. 备注

- 现状扫描：`%` 按钮已经在 `CalculatorPage.ets:278` 存在；`getPercentString` 已经在 `Expression.ets:169` 实现
- 实测验证（Node 镜像）：8/8 百分号语义用例全过，含 `50+10%=55`、`200-10%=180`、`100*10%=10`、`100/10%=1000`、`50%=0.5`、`100+(50*20%)=110`、`(100+50)*10%=15`、`5!%=1.2`
- 本变更关注点：
  1. 确认现有 `%` 按钮在 UI 上可用（位置/颜色/主题）
  2. 用 ETS 单元测试 + Node 镜像"锁定"百分号语义（防止后续重构破坏）
  3. ~~修正 `getPercentString` bug~~ — 经实测**无 bug**，跳过修复
